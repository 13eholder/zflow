# 会话上下文审计

该仓库是一个 Go 实现的存储服务。当前智能体会话在启动时加载了整个 `docs/archive/` 目录（1,800 个文件）、生成的 protobuf 输出、六份旧的故障转录记录以及每份 ADR。但它没有加载活跃的 `CONTRIBUTING.md` 或 `docs/current-architecture.md`。

观察到的故障：

- 响应推荐使用 Java 实现新组件，尽管新源代码必须使用 Go。
- 建议使用 GORM 式 ORM 访问元数据，但此项目的存储引擎层要求直接操作 WAL 和 SSTable。
- 智能体反复忘记副本共识属于复制层而非存储引擎层。
- 经过较长的工具调用轨迹后，回答变得泛化。

当前任务：为某个现有的 RPC 处理程序添加输入验证逻辑。
