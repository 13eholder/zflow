# 智能体角色

角色提供一个稳定的审查视角和输出格式。它们与技能不同：角色回答“谁来评估”，技能回答“某个专业领域如何处理”。

| 角色 | 职责 | 最适用于 |
|------|------|----------|
| [code-reviewer](../agents/code-reviewer.md) | 高级 Staff 工程师 | 对具体 diff、提交或 PR 做独立代码审查 |
| [test-engineer](../agents/test-engineer.md) | QA 工程师 | 测试策略、覆盖缺口和故障路径分析 |

## 三个层次

| 层次 | 作用 | 示例 |
|------|------|------|
| **技能** | 专业领域或明确文档产物的工作流 | `performance-optimization` |
| **角色** | 单一视角与标准报告格式 | `code-reviewer` |
| **命令** | 用户入口或编排层 | `/ship` |

用户或命令负责编排。**角色不调用其他角色。** 普通实现、测试和审查可以直接使用智能体原生能力，不需要通过技能转发。

## 何时直接调用角色

针对单一产物、单一视角的工作直接选择角色：

- “审查这个 PR” → `code-reviewer`
- “这个结账流程缺少哪些测试？” → `test-engineer`

这比增加一个只负责转发的命令或角色更便宜，也能减少摘要过程中的信息损失。

## 何时使用 `/ship`

`/ship` 是本仓库唯一内置的多角色编排：

```text
/ship
  ├── 并行：code-reviewer → 代码审查报告
  └── 并行：test-engineer → 覆盖率报告
                         ↓
                  主智能体合并
                         ↓
              go/no-go + 回滚方案
```

两个角色读取相同变更，但调查互不依赖，因此可以并行。主智能体保留完整上下文并负责最终判断。完整约束见 [编排模式](../references/orchestration-patterns.md)。

## 委派可写实现任务

当主智能体把受已批准 Spec、ADR、冻结接口、模块 ownership 或共享 invariant 约束的实现工作交给可写 sub-agent 时，先使用 `delegated-task-contract`。Contract 归属于一个能够唯一确定的现有 Stage，固定保存到 `stages/<stage-id>/task-contract/<task-id>.md`，并由 `STAGE.md` 前向索引；Contract 不添加 Stage 字段或回链。只有契约达到 `READY`，并且完整契约文本（或精确路径与完整读取要求）随任务一起发送后，才进行分派。

如果不存在 Stage 或候选不唯一，暂停分派并请求用户选择现有 Stage 或显式创建 Stage；不要隐式创建。Contract 状态、偏离和证据变化时同步 `STAGE.md` 摘要，任何非 `COMPLETED` / `CANCELLED` Contract 都会阻止 Stage 封版为 `done`。

这是一道委派边界门禁，不是新的角色或角色路由层。只读探索、独立审查报告和没有语义选择的机械修改不需要该契约。完整联动规则见 [Stage 与 Task Contract 联动规则](../references/stage-task-contract-integration.md)。

## 决策矩阵

```text
是否只需要一个专业视角？
├── 是 → 直接调用对应角色
└── 否 → 是否在做生产发布判断？
         ├── 是 → /ship 并行发散后合并
         └── 否 → 主智能体直接完成；不要新建路由层
```

## 角色规则

1. 一个角色只承担一种职责，并返回一种稳定格式。
2. 角色不调用其他角色，也不创建深层角色树。
3. 发现超出范围的问题时，在报告中建议后续动作，不自行扩张任务。
4. 角色可以读取仓库、运行只读检查和验证命令，但外部副作用仍由主智能体控制。
5. 每个角色文件以“组合”部分说明直接调用和编排入口。

## 添加新角色

1. 创建 `agents/<role>.md`，定义职责、范围、输出格式与规则。
2. 在底部添加“组合”部分。
3. 更新本页顶部的角色表。
4. 只有真实重复出现的并行组合才值得增加新命令，并应同步记录到 [编排模式](../references/orchestration-patterns.md)。
