# OpenCode 设置

OpenCode 可以从技能目录发现 `SKILL.md`，并通过 `skill` 工具按需加载。zflow 在 OpenCode 中采用选择性模型：普通编码使用模型原生流程，只有专业领域或明确文档产物才加载技能。

## 安装

1. 克隆仓库或只复制 `skills/` 目录。
2. 按你的 OpenCode 配置把技能目录加入可发现路径。
3. 确认 `skills/<skill-name>/SKILL.md` 能被 `skill` 工具列出。

仓库根目录的 [AGENTS.md](../AGENTS.md) 只配置维护 zflow 本身，不应复制到其他项目。你的项目应维护自己的简短规则，写明构建命令、目录边界和安全约束。

## 选择性加载

OpenCode 应遵循以下原则：

- 实现、测试、调试、重构、代码审查和 Git 操作不加载 zflow 技能。
- 公共接口、数据承诺、故障注入、性能、可观测性、迁移或生产发布等任务，加载对应专业技能。
- 只有明确要求规范、计划、ADR、来源证据或 Stage 时，加载对应文档技能。
- 默认只加载一个主技能，不自动串联。

示例：

| 用户请求 | 行为 |
|----------|------|
| “实现这个已定义的函数” | 直接实现并验证，不加载技能 |
| “设计对象存储的公共 RPC 契约” | 加载 `api-and-interface-design` |
| “证明节点宕机后确认写不会丢” | 加载 `consistency-and-durability-verification` |
| “依据当前官方文档确认这个框架 API” | 加载 `source-driven-development` |
| “为下周生产发布制定灰度与回滚方案” | 加载 `shipping-and-launch` |

## 推荐项目规则

项目规则只需要表达选择边界：

```markdown
普通开发任务使用模型原生工作流：先检查相关代码与测试，再修改、验证并审查 diff。
只有任务明确匹配 zflow 的专业领域或要求其文档产物时，才调用对应技能。
同一请求默认只使用一个主技能；不要自动串联完整生命周期。
```

不要把全部技能正文放进 `AGENTS.md`，否则会重复占用上下文并稀释触发边界。

## 验证

- 用 `skill` 工具确认 13 个技能可发现。
- 用普通缺陷修复请求确认不会加载技能。
- 用公共协议设计或生产发布请求确认对应技能会被加载。
- 如果路由过宽，收紧技能 `description` 或项目规则，而不是增加路由器角色。

## 局限

OpenCode 的具体技能目录和自动发现行为可能随版本或发行配置不同。若当前版本无法自动发现，可在请求中显式点名技能，或只把当前所需的单个 `SKILL.md` 加入上下文。
